# BAF 插件包

BAF 的企业工作流能力由 **7 个插件包**组成。它们随 baf-dsh **一起安装、一起更新**，无需单独安装或管理；同时也支持**热升级**（会话里执行 `/baf-update`，无需重启应用）。各自的版本号在 **设置 → 版本与更新** 中查看（详见 [版本与更新](updates.md)）。

## 一览

| 包名 | 一句话说明 | 你会直接用到的入口 |
|------|------------|--------------------|
| `@deepseek-ai/dsh-baf-core` | 工作流内核：阶段、门禁、任务结构 | 无（其他包都建立在它之上） |
| `@deepseek-ai/dsh-baf-workflow` | 工作流引擎：流转、派单、多模型路由 | `/baf-go` 等全部流程指令、工作流图页签 |
| `@deepseek-ai/dsh-baf-openspec` | 变更规格：把每次变更写成提案文件 | 自动运行；产物在 `openspec/changes/` |
| `@deepseek-ai/dsh-baf-standard` | 工程规范：指向企业规则源 | 无（模型自动遵循） |
| `@deepseek-ai/dsh-baf-quality` | 质量检查：构建 / 测试 / 覆盖率 / 静态分析门禁 | `/baf-check-quality` |
| `@deepseek-ai/dsh-baf-guard` | 安全守护：文件与命令硬门禁、密钥扫描 | `/baf-check-guard` |
| `@deepseek-ai/dsh-baf-scaffold` | 工程脚手架：一键生成工作区骨架 | `/baf-scaffold`、初始化确认卡 |

## 逐个说明

### baf-core — 工作流内核

定义所有 BAF 功能共用的核心结构：**阶段**（intake → open → clarify → design → plan → implement → verify → archive）、**确认门**（哪些步骤必须停下等你点确认）、**任务**结构，以及**企业基线**的加载与校验（`.baf/baseline.yml`）。

**你怎么用到它**：不直接敲它的命令——但工作流图上的每一格、每一次「停下等确认」，规则都出自这里。基线里没填的企业值会以 `<enterprise-tbd>` 占位，BAF 不会替企业猜策略。

### baf-workflow — 工作流引擎

把会话里的工单沿各阶段流转派发，并驱动**多模型路由**（Commander / Reviewer / Worker 三档，按关键词规则自动升级；在 **设置 → 多模型路由** 配置）。

**你怎么用到它**：BAF 模式的日常全部在这里——

- `/baf-go` 自动推进到下一个需要你确认的点；卡住时再敲一次会**给模型派工单**催它补产物
- `/baf-go-confirm` 不弹框直接过确认门
- `/baf-workflow-open` … `/baf-workflow-archive` 逐阶段指令（补漏与排障用）
- `/baf-status` 看当前变更；`/baf-list` 看工作区全部变更
- `/baf-welcome` 重印启动卡（环境体检 + 绑定）；`/baf-doctor` 自检
- `/baf-version` 看版本；`/baf-update` / `/baf-update-rollback` 插件包热升级

多数操作在**工作流图页签**里点按钮即可，指令是等价的另一条路。完整说明见 [BAF 模式](baf-mode.md)。

### baf-openspec — 变更规格

把每次变更写成 OpenSpec **提案文件**：先起草（open 阶段生成骨架）、随阶段补内容（设计、计划、实现、验证产物）、validate 校验、归档时原子移动到归档目录。

**你怎么用到它**：全自动，不需要敲命令。想看「这次变更到底写了什么」，直接打开工作区的 `openspec/changes/<变更id>/` 目录——每个阶段的产物都是普通 Markdown 文件，可读、可进 git。

### baf-standard — 工程规范

读取企业基线里定义的**编码与流程规范**要点，把模型指向企业的规则源（而不是内置一套通用规则），并为计划校验和门禁消息提供统一的规则域词汇。

**你怎么用到它**：无命令。效果是「模型写代码时遵循的是**你们企业**的规范」；基线未填的部分会明确提示「策略缺失」，而不是悄悄用默认值。

### baf-quality — 质量检查

按基线执行交付门禁：**构建、测试、覆盖率、静态分析**。verify 阶段自动跑；也可随时手动跑。

**你怎么用到它**：会话里输入 `/baf-check-quality`（在 verify 之外单独执行质量检查）；或等 verify 阶段自动执行。结果按门禁逐项列出，哪项不过会明确指出。

### baf-guard — 安全守护

对**文件与命令工具做硬门禁**（哪些路径能写、哪些命令要确认、未绑定工作流时禁止改源码），并在交付前做**密钥扫描**（防止把 API Key 等机密提交进变更）。

**你怎么用到它**：会话里输入 `/baf-check-guard`（手动跑安全门禁 + 密钥扫描）。平时它在后台拦——比如没建变更就想写源码时被拒绝，就是它在起作用。

### baf-scaffold — 工程脚手架

一键生成工作区骨架：`.baf/baseline.yml`（基线清单，企业值以占位符标注）和 `openspec/changes/`（变更目录）。带**人工确认**；绝不静默覆盖——已存在且内容不同的文件会先备份成 `<文件名>.baf-backup-<时间戳>` 再写入。

**你怎么用到它**：会话里输入 `/baf-scaffold`；或在首次使用时点弹出的「初始化工作区」确认卡（走的是同一能力）。

## 版本与更新

- **随应用走**：7 个包随 baf-dsh 一起安装、一起更新，无需单独管理。
- **热升级**：会话里执行 `/baf-update` 检查并更新插件包，无需重启应用；`/baf-update-rollback` 可回滚到上一版。
- 版本明细见 **设置 → 版本与更新**（每个包一行：包名、版本号、一句话说明），或指令 `/baf-version`。
