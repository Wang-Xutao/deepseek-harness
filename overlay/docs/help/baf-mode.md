# BAF 模式（怎么用）

BAF 是面向「改代码要按流程走」的会话模式。选中后，系统按固定阶段推进，而不是只靠聊天口头说「做完了」。

## 三步上手

1. **新建会话**，在 Agent 预设里选 **BAF 模式**。
2. 打开会话顶部的 **「工作流」** 页签（只有 BAF 会话才有）。
3. 在页签底部描述要改什么，点 **新建变更**；或在对话里直接说明需求。

确认分类后才会真正进入流程。确认之前不会改你的源码。

## 完整流程 vs 缺陷快路径（怎么区分？）

**不是**靠另开 slash「选模式」，也**不是**必须新开会话。

| 你看到的模式 | 何时出现 | 含义 |
|--------------|----------|------|
| **模板（空闲）** | 还没有活动变更 | 参考图，方便了解阶段 |
| **完整流程 full-go** | intake 判定：新需求 / 高风险 Bug | intake → open → clarify → design → plan → implement → verify → archive |
| **缺陷快路径 bug-fast-path** | intake 判定：低风险 Bug 且基线允许 | open → implement → verify → archive（缩短） |
| **需先澄清** | 信息不够 | 先问清，再决定走哪条 |

如何确认当前模式：

- 「工作流」顶栏的 **模式**
- `/baf-status`（标准化指令卡，默认展开全文）

### 同一对话里能不能同时有两种模式？

- **一条变更**：只能有一种模式；快路径若风险扩大，在**同一变更内升级**为 full-go（设计如此，不必新开会话）。
- **同一工作区**：可以有多条变更（例如一条 full-go、一条快路径），但 Tab / `/baf-status` 有一个**焦点变更**；并行开发靠多变更，而不是一条变更双模式。

**推荐**：日常用 intake 自动分流；并行需求用多变更或另开会话（同 cwd 仍共享 projection）。不要为「换模式」强行新开空工作区。

## 斜杠指令（系统执行，不是大模型闲聊）

输入 `/` 可选；执行后出现**指令卡片**。`baf-*` 指令**默认展开**全文，便于直接阅读；仍可点行收起。首行是摘要，正文按【分区】格式化。

按功能分三类，**核心**指令无中间缀，**流程**指令加 `baf-workflow-` 前缀（go 工作流阶段），**检查**指令加 `baf-check-` 前缀（基线门禁）。结尾的 ★★ 是常用等级（★★★ 常用 / ★★ 偶尔 / ★ 极少）。

| 指令 | 类别 | 作用 | 常用 |
|------|------|------|------|
| `/baf-help` | 核心 | 列出全部指令与用法 | ★★ |
| `/baf-status` | 核心 | 当前变更：模式 / 阶段 / intake | ★★★ |
| `/baf-version` | 核心 | 与设置「版本与更新」对齐：BAF DSH DESKTOP、DeepSeek Harness，以及各 BAF 插件独立版本 | ★ |
| `/baf-doctor` | 核心 | 自检 cwd 与注册 | ★ |
| `/baf-list` | 核心 | 变更总览（工作区全部变更，含已归档/已放弃） | ★★ |
| `/baf-workflow-open` | 流程 | 启动变更：intake 分类 | ★★★ |
| `/baf-workflow-classify` | 流程 | 分类确认 / 拒绝 | ★★ |
| `/baf-workflow-clarify` | 流程 | 澄清阶段（N2） | ★★ |
| `/baf-workflow-design` | 流程 | 设计阶段（N3） | ★★ |
| `/baf-workflow-plan` | 流程 | 计划阶段（N4） | ★★ |
| `/baf-workflow-implement` | 流程 | 实现阶段（N5 进入/完成） | ★★★ |
| `/baf-workflow-verify` | 流程 | 验证阶段（N6） | ★★★ |
| `/baf-workflow-archive` | 流程 | 归档变更（N7/T14，需 confirm） | ★★★ |
| `/baf-workflow-abandon` | 流程 | 放弃变更（T16，需 confirm） | ★ |
| `/baf-check-quality` | 检查 | 基线 C 栈质量检查（verify 外执行） | ★★ |
| `/baf-check-guard` | 检查 | 安全门禁（verify + secret-scan） | ★★ |

日常多在「工作流」页签完成阶段推进，slash 指令用来补漏与排障；用 `/baf-help` 随时看完整列表。

## 断点续跑（新会话 / 新电脑）

| 场景 | 能否继续 | 说明 |
|------|----------|------|
| 同工作区新开会话 | **能** | 状态在 `<cwd>/.baf/projection/`，与会话 id 无关 |
| 崩溃后重开 | **能** | 从最后一致 projection 恢复（resume 语义；细粒度 handler 后续完善） |
| 换电脑 | **能，若同步了工作区** | 需带上 `.baf/projection/`（是否进 git 由企业策略定；未定时请整仓/工件同步） |
| 只拷贝源码、不同步 `.baf` | **不能** | 会丢阶段状态，需重新 intake |

## 变更总览

在「工作流」页签顶栏点 **「变更总览」**，可查看本工作区 projection 中已记录的变更列表（含当前焦点）。

完整的归档筛选与导出能力仍在建设中；日常也可用 `/baf-status` 或查看工作区 `.baf/projection/`。

## 工作流页怎么操作

- **点击状态卡片**：选中（右侧显示清单与详情）；当前阶段有「当前」醒目标识
- **未作项**：在右侧「本阶段清单」置顶
- **右键拖动**平移；**Ctrl+滚轮**缩放
- 顶栏 **变更总览** / **刷新**；底部可新建变更

## 和「轨迹图」的区别

| 页签 | 看什么 |
|------|--------|
| **工作流** | 变更走到哪一阶段 |
| **轨迹图** | 本轮模型/工具调用轨迹 |

## 版本怎么看

- **设置 → 版本与更新**：**BAF DSH DESKTOP**、**DeepSeek Harness**，以及各 **BAF 插件包**（如 `baf-core` / `baf-workflow`，各自独立 semver）
- **`/baf-version`**：与设置页同源字段，并附带简要特性说明
