# BAF 模式（怎么用）

BAF 是面向「改代码要按流程走」的会话模式。选中后，系统按固定阶段推进，而不是只靠聊天口头说「做完了」。

## 三步上手

1. **新建会话**，在 Agent 预设里选 **BAF 模式**。
2. 打开会话顶部的 **「工作流」** 页签（只有 BAF 会话才有）。
3. 在页签底部描述要改什么，点 **新建变更**；或在对话里**直接说明需求**——空闲工作区（已初始化、无进行中变更）里系统会自动弹一张小卡问「要把这句话作为新需求开始吗？」，点「作为新需求开始」即建立变更，点「只是聊天」则什么都不发生。

### 分类卡：明选，不是盲选

分类确认卡上直接写着**系统初步判断**（完整流程 / 缺陷修复路径、类型、置信度、需求摘要），而且**两个路径都是可点按钮**——判断不合意就点另一条，不用自己拼命令。改判会作为独立事件记入流程档案（审计可查）。

缺陷场景里，模型还会把整理好的**缺陷修复草案**（现象 / 根因 / 涉及文件 / 回归测试 / 测试命令）带进卡里；点「确认 · 缺陷修复路径」**一次点击同时定路径 + 交字段**。

确认分类后才会真正进入流程。确认之前不会改你的源码。

### 打开会话时的启动卡

进入 BAF 会话的第一屏是一张**启动卡**（等于 BAF 的欢迎语），一次说清三件事：

- **环境体检**：workspace / baseline / Git / OpenSpec / C 工具链 / guard+quality / 版本。`✓` 就绪、`✗` 缺失（下面一行给安装引导）、`?` 未探测（例如 C 工具链首屏不探测，进入 verify 时才查）。
- **本会话绑定**：工作区里若还有**未完成的工作流**，这里列出来，并问你是**继续**还是**新开**——不会替你决定。
- **下一步**：给出你现在就能敲的那条指令。

缺件**不会**拦住会话打开，只是提醒；想再看一次启动卡，随时输入 `/baf-welcome`。

> 想改代码但**没有绑定任何工作流**时，写文件的动作会被门禁拒绝。这就是「BAF 模式必须依托工作流」的落地方式：先有变更，再落代码。

## 完整流程 vs 缺陷快路径（怎么区分？）

**不是**靠另开 slash「选模式」，也**不是**必须新开会话。

| 你看到的模式 | 何时出现 | 含义 |
|--------------|----------|------|
| **模板（空闲）** | 还没有活动变更 | 参考图，方便了解阶段 |
| **完整流程 full-go-path** | intake 判定：新需求 / 高风险 Bug | intake → open → clarify → design → plan → implement → verify → archive |
| **缺陷快路径 bug-fix-path** | intake 判定：低风险 Bug 且基线允许 | open → implement → verify → archive（缩短） |
| **需先澄清** | 信息不够 | 先问清，再决定走哪条 |

如何确认当前模式：

- 「工作流」顶栏的 **模式**
- `/baf-status`（标准化指令卡，默认展开全文）

### 同一对话里能不能同时有两种模式？

- **一条变更**：只能有一种模式；快路径若风险扩大，在**同一变更内升级**为 full-go-path（设计如此，不必新开会话）。
- **同一工作区**：可以有多条变更（例如一条 full-go-path、一条快路径），但 Tab / `/baf-status` 有一个**焦点变更**；并行开发靠多变更，而不是一条变更双模式。

**推荐**：日常用 intake 自动分流；并行需求用多变更或另开会话（同 cwd 仍共享 projection）。不要为「换模式」强行新开空工作区。

## 斜杠指令（系统执行，不是大模型闲聊）

输入 `/` 可选；执行后出现**指令卡片**。`baf-*` 指令**默认展开**全文，便于直接阅读；仍可点行收起。首行是摘要，正文按【分区】格式化。

按功能分三类：**核心**（入口 / 查看 / 体检）无中间缀；**流程**（go 工作流阶段）加 `baf-workflow-` 前缀；**检查**（基线门禁）加 `baf-check-` 前缀。`/baf-go` 是流程的自动驱动入口，按约定不带中间缀。结尾的 ★ 是常用等级（★★★ 常用 / ★★ 偶尔 / ★ 极少）。

| 指令 | 类别 | 作用 | 常用 |
|------|------|------|------|
| `/baf-help` | 核心 | 列出全部指令与用法 | ★★ |
| `/baf-welcome` | 核心 | 重印启动卡：绑定 + 工具链体检 | ★★ |
| `/baf-status` | 核心 | 当前变更：模式 / 阶段 / intake | ★★★ |
| `/baf-version` | 核心 | 与设置「版本与更新」对齐：BAF DSH DESKTOP、DeepSeek Harness，以及各 BAF 插件独立版本 | ★ |
| `/baf-doctor` | 核心 | 自检 cwd / 工具链 / 注册 | ★ |
| `/baf-list` | 核心 | 变更总览（工作区全部变更，含已归档/已放弃） | ★★ |
| `/baf-go` | 流程 | 自动推进到下一个**需要你确认**的点（两个确认门会停下）；若当前卡在「等模型补产物」，会顺带给本会话模型**派工单**催它补齐 | ★★★ |
| `/baf-go-confirm` | 流程 | 不弹确认框，直接继续（过确认门 / 确认分类 / 初始化） | ★★ |
| `/baf-workflow-open` | 流程 | 启动变更：intake 分类 | ★★★ |
| `/baf-workflow-classify` | 流程 | 分类确认 / 拒绝 | ★★ |
| `/baf-workflow-clarify` | 流程 | 澄清阶段（N2） | ★★ |
| `/baf-workflow-design` | 流程 | 设计阶段（N3） | ★★ |
| `/baf-workflow-plan` | 流程 | 计划阶段（N4） | ★★ |
| `/baf-workflow-implement` | 流程 | 实现阶段（N5 进入/完成） | ★★★ |
| `/baf-workflow-verify` | 流程 | 验证阶段（N6） | ★★★ |
| `/baf-workflow-archive` | 流程 | 归档变更（N7/T14，需 confirm） | ★★★ |
| `/baf-workflow-abandon` | 流程 | 放弃变更（T16，需 confirm） | ★ |
| `/baf-workflow-resume` | 流程 | 漂移（drift）后复位到合法节点（T13，需选目标节点） | ★★★ |
| `/baf-check-quality` | 检查 | 基线 C 栈质量检查（verify 外执行） | ★★ |
| `/baf-check-guard` | 检查 | 安全门禁（verify + secret-scan） | ★★ |

日常多在「工作流」页签完成阶段推进，slash 指令用来补漏与排障；用 `/baf-help` 随时看完整列表。

### 两个「必须停下确认」的门

无论哪条路径，流程都会在下面两处**停下等你**（首行带 `awaiting_customer_confirm` 标记）：

1. **设计文档已实现**之后（进入计划/实现之前）
2. **验证通过**、进入归档之前

确认方式有三种，任选其一：**确认弹窗**里点「确认」（弹窗没关时会一直等你）、工作流页签点对应按钮、或输入 `/baf-go-confirm` 不弹框直接继续。`/baf-go` 会**重新弹出**确认框——想再看一眼选项时就用它。

有未决确认（分类 / 设计确认 / 归档确认）期间，大模型**不能**用通用提问工具代答或代问工作流决策（会被门禁拦下）——它只能弹出上面这种标准确认卡，由你点选。

### 卡在「等模型补产物」时：再敲一次 `/baf-go`

流程除了两个确认门，还有一类**停靠点**：轮到模型写产物，但模型没在动。典型场景——你在弹窗点了「推进」，`open` 变成 `clarify`、模板已装好，可 clarify.md 一直没人填，界面看着像卡死。

这类停靠点上敲 `/baf-go`，除了照常出卡，还会**给本会话的模型派一张工单**（工单内容包括：变更、阶段、产物路径、裁决门说缺什么、四条执行要求——直接改产物、补齐就结束回合、需要决策用提问卡、本单由你敲 `/baf-go` 生成）。

要点（2026-09-23 更新）：

- **你的动作就会派单**：手敲 `/baf-go` 或 `/baf-go-confirm`、在弹窗里点「推进」选项、工作流页签点「推进」/门卡按钮——这些都算你授权的动作，停靠点上会当场派单，点完流程接着跑，不用再敲一遍。模型自己调工具、系统内部的自动驱动不会派——派单必须由你的动作发生。
- **确认分类也会派单**（2026-09-23）：在分类确认卡（弹窗或工作流页顶部的「确认 · 完整流程 / 确认 · 缺陷修复路径」按钮）点确认后，流程落在模型要写产物的停靠点（完整流程的 proposal / 缺陷路径的回归测试），同样当场派单——不会「确认完就没动静」。
- **初始化工作区后流程自动接续**（2026-09-23）：还没初始化的工作区里说过需求、又在初始化确认卡上点了「暂不」的，之后用 `/baf-go` 重新弹窗并点「初始化工作区」——初始化完成的那一刻，系统会自动弹「新建工作流」确认（引用你当时的原话），点「新建」接着弹分类确认，一路卡片推进到模型开工，全程不需要重打需求或敲「继续」。中途关掉弹窗不丢：再敲 `/baf-go` 会重弹。
- 工单在对话里显示为**只读条目**（署名插件，标题「`/baf-go` 派单」），不是你说的话、没有输入框、不可编辑、也不会被当成你的原话。
- **同一回合内同样缺口只派一次**：模型正在干时再敲不重复打扰（卡片提示「已派单 · 等待补齐」或「模型回合进行中」）。若模型这回合干完缺口仍在（没补齐就收工），再敲 `/baf-go` 会**重新派单**——它会拿到一张新的工单继续补。
- 模型补齐产物后，回合结束系统**自动**弹出下一阶段的裁决卡——添完产物后的弹窗不需要你再敲任何指令。
- `/baf-status` 和 `/baf-go` 现在永远指向同一条变更（旧的「status 显示 A、go 却报 B 已终态」已修）。

排障提示：要是模型补齐了产物、界面仍没有动，先看对话里最后一张卡片的「下一步」段；再敲 `/baf-go` 看是出了新的裁决卡还是又派了新工单。

## 断点续跑（新会话 / 新电脑）

| 场景 | 能否继续 | 说明 |
|------|----------|------|
| 同工作区新开会话 | **能** | 状态在 `<cwd>/.baf/projection/`，与会话 id 无关 |
| 崩溃后重开 | **能** | 从最后一致 projection 恢复（resume 语义；细粒度 handler 后续完善） |
| 换电脑 | **能，若同步了工作区** | 需带上 `.baf/projection/`（是否进 git 由企业策略定；未定时请整仓/工件同步） |
| 只拷贝源码、不同步 `.baf` | **不能** | 会丢阶段状态，需重新 intake |

新开会话时启动卡会列出工作区里**未完成的工作流**并问「继续还是新开」；选继续就是回复 `/baf-go continue`（多条时用 `/baf-go change=<id>`，不替你猜）。

## 变更总览

在「工作流」页签顶栏点 **「变更总览」**，打开总览面板（2026-09-23 升级为 dashboard）：

- 顶部四枚统计：**进行中变更 / 任务 done÷total / 任务完成率（带进度条）/ 已归档**；
- **进行中的变更**表：每行一条——变更 id、模式与当前阶段、任务进度条、累计耗时、token 消耗；
- **归档历史**表：已归档/已放弃的变更同结构列出。

点击任意行（终态也含）即回到流程图并聚焦该变更——归档变更的阶段产物会从归档目录读取，依旧可点开查看。

## 工作流页怎么操作

- **顶部决策按钮**（2026-09-23）：会话里该弹的确认，工作流页**顶部**同步出现对应按钮——工作区未初始化时的「初始化工作区」、变更待分类时的「确认 · 完整流程 / 确认 · 缺陷修复路径 / 重新描述需求」（卡上带系统初步判断与需求摘要）、设计/归档确认门的选项（归档确认会先弹二次确认框）。点按钮与在会话弹窗里点选**完全等价**，走同一通道，状态互相推送同步；缺陷修复路径的五字段表单仍在右侧栏，填完点表单提交一并确认。
- **点击状态卡片**：选中（右侧显示清单与详情）；当前阶段有「当前」醒目标识；**所有阶段（含完成/放弃后的）都可点击回看**，选中只查看、不驱动流程
- 每张卡片显示该阶段**耗时与 token 消耗**（会话无用量数据时显示 —）
- **未作项**：在右侧「本阶段清单」置顶
- **右键拖动**平移；**Ctrl+滚轮**缩放
- 顶栏 **变更总览** / **刷新**；底部可新建变更

## 和「轨迹图」的区别

| 页签 | 看什么 |
|------|--------|
| **工作流** | 变更走到哪一阶段 |
| **轨迹图** | 本轮模型/工具调用轨迹 |

## 版本怎么看

- **设置 → 版本与更新**：**BAF DSH DESKTOP**、**DeepSeek Harness**，以及各 **BAF 插件包**（如 `baf-core` / `baf-workflow`，各自独立 semver）
- **`/baf-version`**：与设置页同源字段，并附带简要特性说明
