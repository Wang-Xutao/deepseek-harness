# 推荐插件

「推荐插件」是设置页里的一个独立区块（设置 → 推荐插件）：官方挑选的开源 dsh 插件在这里以卡片形式列出，可安装、更新、启用、禁用或删除，无需等待应用发版。

每张卡片的名称旁都标注了**插件包名**（如 `dsh-feishu`）——在社区讨论或反馈问题时，直接引用这个名字即可。

## 为什么用推荐插件

- **热更新**：插件清单与插件本体都从网络获取，新插件上架或版本升级后立刻可装，不用等 baf-dsh 发新安装包。
- **面向普通用户**：不需要懂 git、registry 或构建脚本——一切操作都是卡片上的按钮。
- **安全闸门**：版本兼容性和依赖构建脚本都会先弹出确认卡，由你决定是否继续。

## 卡片上的操作

| 状态 | 可用操作 |
|------|----------|
| 未安装 | 安装 |
| 已启用 | 禁用、更新（有新版本时）、删除 |
| 已禁用 | 启用、更新（有新版本时）、删除 |
| 暂不可用 | 只读（清单标记未验证，或本环境没有插件管理器） |

顶部批量条提供：**一键安装**（装齐所有未安装项）、**全部启用**、**全部禁用**、**检查更新**，以及**自动更新**总开关。

每张卡片还有独立的**自动更新**开关：开启后，应用会定期检查该插件的新版本（限清单认可的版本范围），在后台完成升级。

## 两种确认卡

安装或更新时可能依次弹出：

1. **兼容确认卡**：插件声明的依赖版本与当前运行时不同。确认后应用会记录一次版本豁免并继续安装；拒绝则中止。这类插件理论上存在崩溃风险，请只安装你信任的推荐插件。
2. **构建脚本批准卡**：插件的某些依赖带有安装期构建脚本（如 protobufjs）。批准后才会执行。

## 当前推荐

### 飞书（`dsh-feishu`）

[飞书（dsh-feishu）](https://github.com/PGZXB/dsh-feishu) 把 DSH 接入飞书：斜杠命令变成控制面板卡片按钮，卡内审批与提问、流式回复，扫码即可完成配置。安装后按插件主页的说明配置飞书应用凭据即可使用。

### 插件市场（`dshmarket`）

[插件市场（dshmarket）](https://dshmarket.com) 是 DSH 的可视化插件市场：逛一逛，点一下，装好——在应用里直接浏览、搜索社区插件并一键安装。首次安装会出现一次「兼容确认卡」，确认即可。

### 代码库索引（`dsh-codebase-memory`）

[代码库索引（@lovedolove/dsh-codebase-memory-mcp）](https://github.com/LoveDoLove/dsh-codebase-memory-mcp) 为工作区建立**知识图谱式索引**：按结构检索符号与代码片段、追踪调用链、给出架构概览。

**优势**

- **先懂结构，再动手**：图谱回答的是「谁调用了谁、这段逻辑住在哪个模块」，而 grep 只能回答「这个词出现在哪」。改一个跨模块的函数时，模型少走一轮试错。
- **建议更贴合现状**：索引里带着真实的符号与调用关系，模型给出的改动会顺着现有实现走，而不是凭空另起一套写法。
- **体量与活跃度**：上游 `DeusData/codebase-memory-mcp` 是 MIT 协议、4.7 万星、持续更新；本插件把它接成 DSH 原生工具，不必走 MCP 往返。
- **自带可视界面**：插件会拉起图谱浏览页并提供 `/cbm` 状态命令，索引是否建好、覆盖到哪些目录一眼可见。

**注意**：该插件是**桥**，还需要按其主页说明安装原生组件（`codebase-memory-mcp`）；未装原生组件时插件不会注册工具。

### C 语言 LSP 导航（`dsh-code-navigator`）

[C 语言 LSP 导航（dsh-code-navigator）](https://github.com/Islulua/dsh-code-navigator) 把 clangd 接进 DSH，模型侧获得 **C/C++ 的定义跳转、引用查找、实现查找与悬停信息**。

**优势**

- **编译器级事实**：clangd 读的是编译配置与头文件索引，「这个符号在哪定义、谁引用了它」是确定答案，不是文本匹配猜出来的。
- **零额外 provider**：语言服务在本地跑，不消耗模型配额，也不需要另配模型。
- **上游本就有通用 LSP 接入层**：DSH 的 `lsp` 能力本身是 provider 中立的，换语言服务不改模型侧协议；本插件补的是 C/C++ 这条链路与 clangd 的安装引导。
- **跨平台**：Windows 下用 `clangd.exe`，其余平台用 `clangd`，插件主页有对应说明。

**注意**：`clangd` 不随插件分发，需按插件主页说明自行安装并确保在 PATH 中；上游的 `lsp` 只覆盖四个只读操作，编译错误诊断与重命名需要另接诊断类插件。

### 经验沉淀与记忆（`dsh-memory`）

[经验沉淀与记忆（@openviking/dsh-memory-plugin）](https://github.com/volcengine/OpenViking) 是社区里**用量最大**的 DSH 记忆插件（近月下载量在同类中居首）。

**优势**

- **记得住项目背景**：历次对话与结论沉淀为可检索的记忆与上下文，模型不必每次从零开始追问「这个项目之前是怎么定的」。
- **跨会话复用**：一个项目里的多个会话共享同一份记忆，换个窗口接着干不用重新交代背景。
- **用量与维护度**：社区下载量在记忆类插件里遥遥领先，版本迭代活跃，遇到问题更容易找到同路人。

### 经验库沉淀（`dsh-memory-vault`）

[经验库沉淀（@jacklika/dsh-memory）](https://github.com/JackLiKa/jacklika-agent-plugins-repo) 以「**行动前回忆、关键工作后沉淀**」的方式管理经验：Obsidian 兼容的 Markdown 经验库，附带带冲突检测与可选人工确认的沉淀流程。

**优势**

- **沉淀的是经验，不是流水账**：curator 在动作前先回忆既有经验、在关键工作后提炼可复用结论，沉淀的内容本身就是下一次可用的知识。
- **冲突可控**：新沉淀与既有经验冲突时会检测出来，并可选择人工确认，避免把错误结论固化下来。
- **人可读、可版本管理**：经验落在 Obsidian 兼容的 Markdown 库里，能直接读、能 diff、能进 Git，离线可用，不依赖向量服务。
- **配套齐整**：记忆库、curator、向量检索与文件系统工具同仓发布，版本一起走。

## 常见疑问

**问：删除会留下什么？**
答：删除通过插件管理器完整卸载依赖，并清理推荐插件自动写入的兼容调整（如重复模块的禁用行）；你的其他设置不受影响。

**问：清单从哪里来？**
答：应用内置一份推荐清单，可通过 `/baf-update` 的插件通道热更新；新插件上架后重启应用即可在设置页看到。

**问：安装失败怎么办？**
答：确认网络可达 npm 镜像后点「安装」重试；兼容确认卡出现时需先确认。仍失败时查看卡片上的错误提示，或参考[常见问题](faq.md)。
