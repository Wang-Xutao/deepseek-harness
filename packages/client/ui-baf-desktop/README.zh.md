# @deepseek-ai/dsh-client-ui-baf-desktop

[English](README.md) | 中文

面向 baf-dsh 的桌面 UI：空状态标题后的黑白 Sora 标、baf-dsh 自有标题行（覆盖 `ui-brand-official` 的上游品牌字）、侧栏「帮助」面板（内嵌 MkDocs `/help/`，可在浏览器中打开），会话框的「美化 / 回退」控件，以及把用户叫回会话的桌面通知。

## Desktop notifications

需要你离开窗口的三种状态各发一条系统通知：**任务完成**、**任务出错**、**任务等你处理**（工具审批、提问、计划审阅）。通知的粗体行说明发生了什么，正文行点名是哪个会话；点击通知会把窗口唤回——当应用缩在托盘里时，这正是这条提醒的意义。

渲染端是唯一能看到会话生命周期的一方，由它上报事件；**桌面外壳决定是否弹出**——`desktopNotifications` 偏好就是开关，且由外壳持有，因此在「通用」设置里切换后立即生效，无需刷新。不在 Electron 里就没有任何通知。

一轮停止还不是最终结果：Agent 上报失败与运行状态落下的时机相同，先后顺序也不定。控制器因此在一小段窗口后只结算一轮：若失败已到达，就报失败而不是「完成」——一轮只产生一条通知，而且写明是失败。

观察者挂在全窗口的 `shell.overlay` 层，因此它看到列表里的每个会话——不只是当前打开的那个——并且它不渲染任何东西：通知属于操作系统，不属于页面。

## 应用内更新弹窗

桌面外壳发现更新时，由应用自己来画这个提示。以前是操作系统的消息框——在一个处处自绘的产品里，它看起来像个外人；现在它就是应用自己的对话框：同样的遮罩、同样的卡片、同样的按钮。

分工按产品的粒度来：**外壳决定，应用来画。** 外壳知道是哪个 scope 触发的、更新是不是强制的；它把事实交给渲染端（scope 摘要、更新说明、目标版本），并一直留着，直到下一次提示——所以晚挂载的渲染端也能找到它。渲染端负责画，也负责那三个回答。

两种形态，一张脸。可选更新给出「立即更新」和「稍后更新」——遮罩、Esc 和关闭按钮都能把它关掉。强制更新（强制安全版，或最低桌面版本高于已装版本）说「必须更新后才能继续使用」，给出「立即更新」和「退出应用」，并且**拒绝一切关闭路径**：没有关闭按钮，Esc 也不管用。老版本不许继续跑。

更新说明按要点分段，用户扫一眼列表，而不是读一整堵字。

真正执行更新仍然是外壳的事：进度以推送形式到达，结果随回执回来；失败时弹窗留着并写明原因——用户可以重试，强制更新时也可以选择退出。

## Composer tidy-up control

「美化 / 回退」控件位于会话框右侧操作区，在模型选择与发送按钮之前。它把当前草稿整理成结构清晰的需求简报——小标题、要点列表、代码围栏——并**优化作者已经写下的措辞**：让意图更准确、更具体、更无歧义。它绝不添加草稿里没有的事实、需求、命令、路径或数字，也绝不扩大范围；确实无法判断的地方标成「（待确认）」，而不是替作者做决定。

整理走的是**当前会话自己的模型**——用户在模型选择器里挑的那一个，按 agent loop 解析每一步的同一顺序定位（会话记录的模型选择 → agent 的实时路由选项 → 上次请求头），BAF「自动」伪路由则由部署方的 per-step route resolver 映射为该档位实际会用的路由。控件请 Host 用一次辅助请求（`purpose: 'draft-format'`）整理草稿：草稿是唯一的输入，答案在写回草稿前先过一遍清洗器（围栏、客套话、连续空行）。用户不需要任何配置——用的就是他正在对话的那个模型。

当模型答不出来时（会话还没路由过模型、供应商报错、或答案为空），控件**回落到本地确定性整理器**：分段、要点列表、代码围栏，不改写任何一个字，同一份草稿永远得到同一结果。正是这条回落让控件安全：多话或失败的模型最多退化成「没有变化」，绝不会把草稿弄坏。

控件也会**说明这一次是谁答的**：结果会落到应用级提示条（`shell.overlay` 这一层比输入框活得久），控件自己的提示里也点名真正优化草稿的那个模型，或说明是本地规则接手，或说明模型读过这段文字后认为无需调整。静默回落看起来正好就是「模型没生效」，所以结果永远可见——不必把指针停在控件上才能看见。

模型工作期间控件显示旋转指示并说明状态。若作者在这期间改了草稿，本次结果被丢弃——作者的输入优先。

整理之后控件变为「回退」，按下即还原作者原文。

两态的字形是**同一个物件的两个注解**：同一张文档，「美化」态是一支笔（`list-pen-outline`），「回退」态换成一支实心向左的箭头（`undo-doc-outline`，平台图标集里为此新增的一枚字形）——字重、填充语言与文档轮廓完全一致。美化态的 hover 文案是「格式化输入」；回退态的文案说明后果（「还原美化前的原文」，若用户在美化之后又编辑过，则提示「会丢弃美化之后的修改」）。

## Model Experience

### Composer tidy-up request

#### What the model sees

作者草稿本身，作为一次辅助请求里唯一的 user message，套在固定的 `DRAFT_FORMAT_SYSTEM` 提示词下。会话里的其它内容都不进入这次请求，整理后的答案也不写回会话日志——草稿由会话框自己持久化，所以会话日志仍能重建模型实际看到的东西。

#### Token effect

每按一次发一次辅助请求（`purpose: 'draft-format'`），输出上限为 `DRAFT_FORMAT_MAX_TOKENS`，走会话当前的路由，因此不涉及第二个供应商、也不涉及第二把密钥。若这一按找不到已路由的模型，则什么都不发。

#### KV Cache effect

这次请求只带一个固定系统提示词和一条 user message，没有会话前缀，因此既不读也不写会话级缓存；那个固定提示词本身是供应商可能自行缓存的稳定前缀。

## Known Limitations and Deferred Work

- **品牌字覆盖上游 wordmark** — `ui-brand-official` 在 `sidebar.brand.name` 注册 "DeepSeek Harness"；baf-desktop 之后挂载并注册 `baf-dsh v0.0.14` 让标题行展示正确品牌。需要随 `overlay/desktop/VERSION` 一起 bump。
- **品牌行让位的是品牌名，不是版本胶囊** — 侧栏品牌行的内容列很窄（默认列宽下只有 256px），所以先被省略的是品牌名；旁边的版本胶囊保持完整宽度，因为那枚胶囊正是「更新」标签要说的那个事实。
- **帮助站依赖静态产物** — 需将 `overlay/site` 同步到 `apps/web/dist/help/`（`overlay` 下 `npm run docs:build` 或 `brand-web`）。
- **「在浏览器中打开」** — 桌面壳走 `window.bafDesktop.openExternal`；纯浏览器则用 `window.open`。
- **含 @ 文件引用的草稿不动** — 会话框以纯文本回写草稿，那会丢掉作者挂上的引用 chip。控件保持可见但拒绝处理这份草稿，并说明原因。
- **整理要花一次模型调用** — 整理草稿现在会在会话自己的路由上发一次辅助请求，因此会消耗该供应商的 token、耗时也取决于模型。只有在没有任何模型可用时才会走本地整理器，所以有模型时这一按并非免费。
- **整理结果只有一个快照** — 连按两次不会撤销第一次整理；「回退」恢复的是第一次整理之前的原文。
