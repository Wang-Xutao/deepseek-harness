# @deepseek-ai/dsh-client-ui-baf-workflow

[English](README.md) | 中文

BAF 会话的 **「工作流」** Tab：go 状态机 SVG 流程图、intake 分类卡、阶段详情轨与半交互操作。Host 半边提供 `bafWorkflowView` Typert Remote，经 `@deepseek-ai/dsh-baf-workflow` 读写工作区 projection。

## 工作流页面

项目级的「工作流」页由本包注册在 `settings.workflow.item` 下的若干行拼成：**变更总览**台账、**确认门**台账与**测试流图**行。其中两页共用同一套页面骨架——标识区（BAF 徽标、眉标、标题、说明）、一排指标牌、内容区——所以这一页读起来是一个界面，而不是同一菜单里碰巧挨着的三块屏。

### 变更总览 —— 变更台账

台账列出当前项目的全部变更，已放弃的变更同样是记录在册的行。标识区的两个动作**分级**：导出看板是金色主按钮，刷新是幽灵按钮并带可见的键盘焦点环。往下是一道分区头（眉标、条数、提示、一条发丝分隔线）引出卡片网格，每张卡的任务进度条按变更自身的状态着色——进行中是金、已完成是绿、已放弃是灰。悬停时卡片掠过一层金箔扫光，卡片本身可聚焦。这里的金是点缀而不是填充：页首金洗、选中态金环、卡片金边与状态片的金底各自只余先前的零头，于是这一页读起来是「带金色身份的台账」，而不是「一片金色的场地」。

### 确认门 —— 确认门台账

确认门台账展示流程与守在每个阶段门口的门禁。标识区报出页面身份，三枚指标牌承载实时计数（确认门 / 阶段门禁 / 状态节点）。这些计数原先挤在流程图画布的控制条里，页面身份要靠读者从一张图里推出来；现在它们是页面级指标，控制条则重新说回「这张图是什么」。「需求输入」节点仍是这一页的第一个标记、在入场顺序里的位置不变，但它不再是一整块金色实心板：浅底 + 金色发丝边 + 淡金环的轻标记，不再压过它所处的那张画布。

### 产物预览

变更的文档产物在原地预览窗里打开——与测试流图的配置文件用的是同一个窗口（标题、路径、正文，以及「在侧栏打开」的页脚动作）。预览是更快的读法，不是侧栏的替代品：页脚动作仍把产物送进右侧栏。该页是项目级的、自己背后没有会话，所以读文档时借用同一工作区里一个活跃会话。

## Model Experience

### Composer tidy-up request

#### What the model sees

作者草稿本身，作为一次辅助请求里唯一的 user message，套在固定的 `DRAFT_FORMAT_SYSTEM` 提示词下。会话里的其它内容都不进入这次请求，整理后的答案也不写回会话日志——草稿由会话框自己持久化，所以会话日志仍能重建模型实际看到的东西。

#### Token effect

每按一次发一次辅助请求（`purpose: 'draft-format'`），输出上限为 `DRAFT_FORMAT_MAX_TOKENS`，走会话当前的路由，因此不涉及第二个供应商、也不涉及第二把密钥。若这一按找不到已路由的模型，则什么都不发。

#### KV Cache effect

这次请求只带一个固定系统提示词和一条 user message，没有会话前缀，因此既不读也不写会话级缓存；那个固定提示词本身是供应商可能自行缓存的稳定前缀。

## Known Limitations and Deferred Work

- 阶段开始 / 归档确认按钮在 Phase 5 handler 落地前可见但禁用。
- Electron `baf:getWorkflowStatus` IPC 属 Phase 8；Web 仅走 Typert Remote。
- Tab 在 web 面注册；内容要求 `agentPreset === baf`。
- **整理请求需要一条已路由的模型** — 从未发过请求的会话没有路由，`formatDraft` 回答 `unavailable`，由会话框的本地整理器接手。
- **路由按 agent loop 自己的顺序解析** — 会话记录的模型选择 → agent 的实时路由选项 → 上次请求头；BAF「自动」伪路由由部署方的 per-step route resolver 映射为具体 provider/model。伪路由本身绝不交给 provider；三条来源都没有时回答 `unavailable`。
- **产物预览需要同一工作区里一个活跃会话** — 该页自己没有会话可读，工作区里没有会话时预览会报告读不到该文档。
