# 高风险代码评审清单（SORA / baf-standard）

> 凡自有代码中出现 **动态分配 / `goto` / 递归**（或用户明确授权的其它高风险点），MR/评审 **必须**附本清单并勾选。
> 白名单路径（`third_party` / `sdk` / `bsp` 等，见 `.baf/standards/third-party-whitelist.json`）内第三方源码一般不强制本清单，但 **修改** 第三方仍须单独授权并记录。

## 自有代码高风险（必填）

- [ ] 用户/负责人已 **明确确认** 允许使用该高风险手段（会话或书面记录可追溯）
- [ ] 源码处有 `/* HIGH-RISK: <type> — confirmed: <reason> */` 注释
- [ ] 已说明 **为何不能** 用静态缓冲 / 状态机 / 迭代等替代方案
- [ ] 已评估失败路径、资源上限、栈深度或碎片风险
- [ ] 已补充或说明测试（含边界 / 失败注入，若适用）
- [ ] 评审人已知悉并在本 MR 留下明确意见（批准 / 有条件批准）
